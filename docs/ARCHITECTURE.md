## Состояние и правила

`State` содержит массив из 361 клетки, счётчики захваченных камней, текущего игрока, победителя, число ходов и параметры правил. Значения клетки: 0 — пусто, 1 — чёрные, 2 — белые. `winner == 3` означает ничью.

`State::legal()` и `State::play()` строят `Board` (ниже) и вызывают её правила: правила записаны в одном месте, и игра с поиском не могут разойтись. Отклонённый ход не меняет `State`. Новая своя пятёрка проверяется по осям через поставленный камень.

Открытая тройка определяется через окно `.XXXX.`: после рассматриваемого хода внутри окна должны стоять три своих камня и оставаться одно пустое место; оба конца пусты. Исходный ход должен входить во внутренние четыре клетки. Одна ось учитывается один раз, даже если подходит несколько окон. Таблица `Board` кодирует девять клеток оси; отдельная медленная реализация правил в `tests/pattern_tests.cpp` проверяет эквивалентность.

`play()` сначала проверяет допустимость, затем применяет все захваты и проверяет исход:

1. Десять захваченных камней дают победу текущему игроку.
2. Если предыдущая пятёрка осталась цела после ответного хода, выигрывает её владелец.
3. Новая пятёрка даёт немедленную победу, если нет спасительного захвата.
4. Иначе `pending` хранит владельца пятёрки, которую необходимо разрушить следующим ходом.

`captureDefense()` рассматривает пустые клетки и моделирует захваты противника. Ответ должен разрушить все пятёрки либо сразу выиграть захватом. Обычный ход без захвата не может быть ответом на уже собранную ожидающую пятёрку. Проверка перечисляет существующие опоры возможных захватов вместо симуляции каждой пустой клетки; результат сравнивается с полным перебором в тестах. Захваты освобождают клетки для дальнейшей игры.

`Session` хранит список действий: ходы, выбор цвета и запрос дополнительных камней Swap2. Undo и просмотр истории воспроизводят нужный префикс партии, используя те же правила. Загрузка сначала проверяет и полностью воспроизводит файл во временной сессии, затем заменяет текущую. Повреждённый файл не портит начатую игру. Сохранение использует временный файл и переименование.

## Быстрая доска для поиска (`rules/board`)

`Board` — представление позиции только для поиска. Доска 19×19 окружена рамкой из четырёх клеток-стен (27×27), поэтому окна паттернов не проверяют границы. Ход выполняется на месте (`make`) и отменяется (`unmake`) по записи `Undo`: поставленный камень, до 16 снятых захватом камней, прежние счётчики, победитель и ожидающая пятёрка. Копирование позиции в рекурсии больше не нужно.

При каждом изменении клетки инкрементально обновляются:

- **коды линий**: для каждой клетки и каждой из четырёх осей — 16-битный код восьми соседей (по 4 с каждой стороны, 2 бита: пусто, X, O, стена). Камень меняет код 32 клеток — тех, что видят его на своих осях;
- **сводка клетки** для каждого цвета: форма на каждой оси, число пар для захвата, флаги открытой тройки (правило) и угрозы захвата, итоговый тактический уровень. Обновляется только изменившаяся ось и только у пустых клеток; освобождённая клетка пересчитывается целиком;
- **ключ Zobrist** (64 бита; к нему при запросе добавляются ход, захваты, ожидающая пятёрка и правила);
- **счётчик соседей** в квадрате 5×5 — кандидаты на ход.

Для всех 65 536 кодов и обоих цветов при старте вычисляется таблица `LineInfo` (`patterns.cpp`): форма, число захватываемых пар, флаги. Форма определяется рекурсивно (классическая классификация гомоку):

| Форма | Смысл после хода в клетку |
| --- | --- |
| `Five` | пять и более подряд через этот камень |
| `Flex4` | открытая четвёрка: две и более клетки дают пятёрку |
| `Block4` | четвёрка: ровно одна клетка дополнения |
| `Flex3` / `Block3` | одним ходом получается `Flex4` / `Block4` |
| `Flex2` / `Block2`, `Flex1` / `Block1` | так же, ещё на ход дальше |

Уровень клетки объединяет четыре оси: пять; открытая четвёрка (или две четвёрки — один блок не остановит); четвёрка + открытая тройка; четвёрка; две открытые тройки; открытая тройка. Его берут из таблицы по четырём формам.

После хода `Board::make()` проверяет исход в порядке задания: десять захваченных камней, не разбитая соперником пятёрка, новая пятёрка с проверкой защитного захвата. Двойная тройка определяется тем же окном `.XXXX.`, исключение для захватов сохранено. `tests/pattern_tests.cpp` сравнивает легальность каждой клетки, результат хода, ключ после make/unmake и пересобранный ключ с отдельной медленной реализацией правил на случайных партиях и позициях — около 2,5 млн проверок.

## Поиск

Minimax максимизирует результат для одного игрока и минимизирует для другого. В Negamax обе стороны используют одну функцию: оценка позиции выражается с точки зрения игрока, которому ходить, поэтому оценку ребёнка меняют на противоположную:

```text
score = -negamax(depth - 1, -beta, -alpha, ply + 1)
```

`alpha` — лучший уже найденный результат. `beta` — граница, после которой противник не позволит попасть в эту ветку. Когда `alpha >= beta`, оставшиеся продолжения узла можно отсечь.

Порядок работы `AI::search()`:

1. **VCF** (победа непрерывными четвёрками) для стороны, которая ходит: атакующий ставит только четвёрки, защитник может закрыть клетку пятёрки, захватить пару, выиграть первым. Бюджет — 4 000 узлов и до 10 ходов атакующего. Найденная форсированная победа играется сразу.
2. **Итеративное углубление** 1, 2, 3, … Ход возвращается из последней полностью завершённой итерации. До глубины 10 поиск прерывается только победой следующим ходом: более длинный найденный мат может быть ложным из-за сужения ответов, и следующая итерация его проверяет.
3. **Lazy SMP**: до трёх вспомогательных потоков (всего не больше 4 и не больше числа логических ядер) ищут ту же позицию со сдвинутых глубин и делятся только таблицей транспозиций. Результат берётся из главного потока; помощники лишь заполняют таблицу.

Внутри узла:

- **Терминальные позиции**: победа стоит `Win − ply` (10 000 000 минус число полуходов). Поэтому ИИ выбирает самую быструю победу и самое долгое сопротивление. Отсечение по дистанции мата сужает окно.
- **Таблица транспозиций**: точная/нижняя/верхняя граница, глубина, лучший ход.
- **Генерация ходов** по тактической ситуации (в квисценсе и VCF клетки без четвёрок, угроз и захватов отбрасываются по готовой сводке ещё до расчёта порядка и легальности):
  - есть свой выигрыш (пятёрка или десятый захват) — он первый;
  - у противника пятёрка на доске, которую можно разбить, — только захваты;
  - у противника есть ход к пятёрке или к десятому захвату — только блок, захваты и, если до горизонта не меньше 4 уровней, ход, создающий угрозу захвата (он делает будущую пятёрку уязвимой);
  - противник может сделать открытую четвёрку (открытая тройка) — блоки, свои четвёрки, захваты, угрозы захвата;
  - иначе — все кандидаты.
- **Порядок ходов** (лениво, выбором максимума — в среднем узел отсекается после 1–2 ходов): ход из таблицы, свой выигрыш, блок выигрыша соперника, затем сумма атакующих и защитных форм клетки, захваты, killer-ходы и history-счётчики.
- **PVS**: первый ход — полным окном, остальные — нулевым окном `[-alpha-1, -alpha]`; при улучшении alpha — перепроверка.
- **Выборочная ширина**: в корне 24 спокойных хода, в узле с оставшейся глубиной `d` — `3 + d/2`. Свои четвёрки, ход из таблицы и все ответы на угрозу пятёрки ищутся сверх лимита.
- **LMR**: с третьего ищущегося хода спокойные ходы (не четвёрки, не захваты, не блок четвёрки) сначала смотрятся на 1 уровень мельче (с седьмого — на 2), при `d ≥ 3`. Если ход неожиданно лучше alpha — перепроверка на полной глубине.
- **Квисценс** на горизонте: тихая позиция (нет пятёрки и открытой тройки, на которые надо ответить) оценивается статически («stand pat»). Иначе ищутся ответы. Свои ходы за горизонтом — до трёх лучших двойных угроз (четвёрка + тройка, открытая четвёрка) и одна лучшая простая четвёрка; на открытые тройки отвечаем только первые 2 полухода, всего не глубже 8 полуходов. Это убирает эффект горизонта: позиция с висящей четвёркой не оценивается как спокойная.

### Время

Цель — 420 мс. Глубина 10 (`AI::MinimumDepth`) может дорешиваться до жёсткого предела 472 мс (цель + 1/8). После глубины ≥ 10 следующая итерация не начинается, если её прогноз (время последней × рост относительно предыдущей, от 1,5 до 4 раз) выходит за цель. Часы — `steady_clock`; проверка — раз в 1 024 узла и по флагу остановки для помощников.

## Эвристика

`AI::inspect()` в `evaluation.cpp` проходит все пустые клетки рядом с камнями и для каждого цвета спрашивает: что даст камень здесь на каждой оси? Позиция сильна угрозами, которые она держит в запасе. Компоненты для каждого цвета:

| Компонент | Что считается |
| --- | --- |
| Lines (`alignments`) | сумма значений форм по осям: 0, 1, 4, 10, 40, 60, 400, 500, 8 000, 50 000 для None…Five |
| Figures | клетка с открытой четвёркой или двумя четвёрками +20 000; четвёрка + тройка +12 000; две открытые тройки +5 000 (если ход разрешён правилом); захват, совмещённый с тройкой/четвёркой, +5 000; две и более клетки пятёрки (их не закрыть одним ходом) +100 000 |
| Potential | ход, захватывающий пары: `(2 500 + 1 500 × уже захваченных пар) × пар`, +2 500 за несколько пар, +250 000 если это десятый камень |
| Captured | уже захваченные пары: 0, 6 000, 14 000, 30 000, 70 000 — каждая следующая дороже |
| History | поправка по последним 12 реальным действиям (ниже) |
| Center | небольшой бонус за близость камней к центру |

Место для пятёрки учитывается автоматически: в коде `O . X X . O` пятёрку построить негде, и форма клетки — `None`. Итог — сумма компонентов своего цвета минус соперника, ограниченная ±5 000 000, что ниже любой доказанной победы. Статическая оценка симметрична; очередь хода учитывается поиском (квисценсом), а не оценкой.

Веса подобраны партиями движка против предыдущих версий. Нелинейная цена захватов, например, выиграла 17:7 у линейной (1 600 за камень).

### Динамическая часть

`AI::historyProfile(session)` (`history.cpp`) воспроизводит последние 12 реальных действий с правильным исходным состоянием. Начальная расстановка Swap/Swap2 и выбор цвета пропускаются. Для каждого цвета рассматривается связь между последовательными собственными ходами: горизонталь, вертикаль и две диагонали при расстоянии не более четырёх клеток. Повторения накапливают вес оси; реальные захваты накапливают вес склонности к захватам. Более поздние действия получают вес 1–4, сумма каждой характеристики ограничена восемью.

Значение форм на оси получает `min(value, 5000) × axisWeight / 32`, потенциальный захват — `min(captureValue, 5000) × captureWeight / 16`. Профиль строится один раз для каждого `AI::act()`, фиксирован на время поиска и не обучается на воображаемых ветках.

## Таблица транспозиций

2^20 записей по 16 байт (16 МБ); при нехватке памяти — 2^16, при полной нехватке поиск работает без неё. Запись — два 64-битных слова: данные (оценка, лучший ход, глубина, граница, поколение) и ключ, сложенный XOR с данными. Потоки пишут без блокировок; разорванная запись другого потока просто не проходит проверку ключа.

Таблица сохраняется между ходами в одном объекте `AI` (интерфейс держит один движок на всю программу). Записи прошлых ходов используются только для порядка ходов. Отсечения разрешены лишь записями текущего поиска: прошлые оценки получены выборочным поиском с другим профилем истории. Замещение предпочитает более глубокие записи текущего поиска. Доказанные результаты хранятся относительно узла (`Win − ply` пересчитывается при чтении).

## Интерфейс и измерения

ncurses вызывается только главным потоком. ИИ получает копию позиции через `std::async`; главный поток продолжает перерисовывать таймер и принимать выход/паузу. Один объект `AI` живёт всю программу, чтобы таблица транспозиций переходила от хода к ходу; объявлен до `future`, поэтому поток поиска завершается раньше разрушения движка. Пока идёт поиск, изменение партии заблокировано, чтобы результат не применился к другой позиции. При завершении результат забирается через `future`.

Глубина на экране — последняя завершённая итерация выборочного поиска; рядом — selective (самый глубокий полуход вместе с квисценсом) и пометка VCF, если победа найдена поиском угроз. Число узлов включает незавершённую итерацию и вспомогательные потоки. PV восстанавливается из текущей таблицы и может оказаться короче глубины из-за вытеснения записей; это диагностический пример продолжения.

Клавиша `V` переключает панель на шесть компонентов оценки для чёрных X и белых O: линии, возможные захваты, уже захваченные камни, фигуры, динамическая история и близость к центру. Таймер остаётся видимым. Это оценка отображаемой позиции; она может отличаться от Score, полученного из глубокого поиска.

Для защиты стоит подготовить позиции с захватом в нескольких направлениях, разорванной двойной тройкой, уязвимой пятёркой и победой десятым захватом. Затем показать `make test`, `make sanitize`, `make ui-test` и `./Gomoku --bench`. Проверяйте фактическое время и глубину на компьютере проверки; результаты одного ноутбука не гарантируют такие же результаты на другом.


## Дебютные протоколы

`Rules::opening` задаёт Standard, Pro, Swap или Swap2. Pro проверяется в `State::legal()`, поэтому человек и поиск ИИ используют одинаковые ограничения. Хеш включает тип дебюта и фазу первых трёх ходов Pro.

Swap/Swap2 управляются в `Session`: это последовательность действий игроков, а не обычное чередование владельцев камней. `actor()` возвращает номер действующего игрока, `state.turn` — цвет следующего камня. Пока `blackPlayer == 0`, цвета ещё не распределены. Первые три камня ставит игрок 1. После них выбирает игрок 2. При `Extend` два дополнительных камня ставит игрок 2, а окончательный выбор делает игрок 1. После выбора `blackPlayer` хранит владельца чёрных; белые всегда делают следующий обычный ход.

Фаза определяется числом поставленных камней, флагом `extended` и распределением цветов. Выбор невозможен до нужного количества камней; постановка заблокирована во время выбора; повторное расширение запрещено. Начальная расстановка не выполняет захваты. Правила выбранной партии действуют после её завершения.

`AI::act()` отличает обычный поиск от действий в дебюте. Для расстановки выбирает позицию с небольшой абсолютной статической оценкой, чтобы не предложить сопернику очевидно сильный цвет. При выборе цвета выполняет обычный ограниченный по времени поиск и выбирает сторону с лучшей оценкой. Сам ИИ не запрашивает расширение Swap2; дополнительную расстановку и окончательный выбор после запроса человека поддерживает.

Формат `GOMOKU 2` хранит тип дебюта и события `M x y` / `C choice`. Состояние фаз и владельцев цветов восстанавливается воспроизведением событий. Старый формат `GOMOKU 1` читается как Standard. Undo сначала строит предыдущее состояние, затем заменяет текущее, чтобы ошибка выделения памяти не повредила историю.


## Ограниченные буферы

`FixedList` ограничивает список кандидатов размером доски (361), а PV — 64 ходами; глубина рекурсии ограничена 64 полуходами. В рекурсии нет векторов и выделений памяти. Первым в PV всегда показывается фактически возвращённый ход; остальные записи — диагностическое продолжение из таблицы.

## Тестирование отказов памяти

`tests/fault_allocator.cpp` подключается только к тестовым исполняемым файлам. Он заменяет C++ new/new[] и позволяет отклонять запросы после заданного числа успешных выделений, либо постоянно. Проверяются неизменность партии при неудачном ходе/undo/load, работа ИИ без таблицы и профиля истории, восстановление после возврата памяти и начальная расстановка Swap.

`tests/ui_memory.py` запускает отдельный `build/Gomoku-oom` через PTY. SIGUSR1 включает постоянный отказ, SIGUSR2 разрешает выделения снова. После отказа проверяются сообщение, управление меню, новая партия, восстановление подсказок и выход при вновь запрещённых выделениях. В обычный `Gomoku` тестовый аллокатор не входит.

Живая позиция рисуется без копирования вектора истории на каждом кадре. Если не хватает памяти для истории/операции, catch возвращает просмотр к живой позиции, отключает диагностическую панель и автоматические ходы: пользователь сохраняет управление. Кэш AI и рабочие структуры потоков выделяются через nothrow; без кэша поиск продолжается, без рабочей структуры возвращается легальный резервный ход. Если поток не создаётся, поиск идёт с теми потоками, что есть. Системные библиотеки и принудительное завершение процесса ОС не охватываются тестами C++ new.

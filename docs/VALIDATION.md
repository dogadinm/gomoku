# Результаты проверки

Проверено 15 ноября 2026 года на arm64 macOS с Apple Clang. Замеры относятся к этому компьютеру и этой выборке, а не ко всем возможным партиям.

## Функциональность и ошибки памяти

- `make test`: 4 525 проверок правил, тактики, сохранения, истории и дебютов; ещё 25 422 сравнения оптимизированных проверок с медленным эталоном.
- `make sanitize`: оба набора проходят под AddressSanitizer и UndefinedBehaviorSanitizer.
- `make ui-test`: управление ncurses через настоящий PTY, подсказка, панель оценки, undo, сохранение/загрузка, Swap2, просмотр истории, изменение размера и выход.
- `make memory-test`: 35 проверок отказа C++ выделений в ядре и отдельный сценарий постоянного отказа в UI с восстановлением и выходом.
- macOS `leaks --atExit` для основного набора и набора отказов памяти: 0 утечек, 0 потерянных байт в обоих прогонах.

Сравнение с эталоном включает 6 561 вариант одной оси, пересекающей открытую тройку, 6 000 случайных досок с краями/цветами/настройками, а также позиции с пятёркой, для которых защитный захват проверяется полным перебором пустых клеток.

## Глубина и время

`make performance-test` строит партии детерминированным генератором с seed 1701 и берёт позиции на разных стадиях. Поиск использует реальный профиль истории, как интерфейс.

Результат итогового прогона:

| Показатель | Результат |
| --- | ---: |
| Всего позиций | 90 |
| С терминальной оценкой выбранного дерева | 61 |
| Остальные позиции | 29 |
| Минимальная завершённая глубина остальных позиций | 10 |
| Позиции без терминальной оценки с глубиной менее 10 | 0 |
| Среднее время по всем позициям | 88,0 мс |
| Среднее время по позициям без терминальной оценки | 244,5 мс |
| Максимальное время | 420,1 мс |

Терминальная оценка может остановить поиск раньше десяти уровней. В выборочном дереве это не доказательство оптимальности по всей доске. Тест завершается ошибкой, если нетерминальный результат не достиг десяти или среднее время превысило 500 мс. На другой машине время и достигнутая глубина могут отличаться.

## Автоматические соперники

`make arena-test`: два варианта начала, игра каждым цветом против соперников с глубиной 1 и 3 — восемь партий. Соперники используют тот же набор правил, оценку и проверки немедленных угроз, но ограниченную глубину. Это не независимые турнирные движки.

| Показатель | Результат |
| --- | ---: |
| Победы основного ИИ | 8 |
| Поражения | 0 |
| Ничьи / незаконченные партии | 0 / 0 |
| Ходы основного ИИ | 99 |
| Ходы без терминальной оценки с глубиной менее 10 | 0 |
| Среднее время основного ИИ | 112,3 мс |
| Максимальное время | 420,0 мс |

Все партии сохраняются в `build/arena-*.save`. Отчёт — `build/arena-results.txt`. Цель обнаруживает поражения, недобор глубины и превышение среднего времени. У незаконченной за 80 полуходов партии отдельная категория: она не объявляется ничьей.

## Практические пределы

Ограничения ширины спокойных продолжений сохранены: 16 → 6 → 4 → 2. Сильные угрозы и проверенные защиты сохраняются сверх лимита. Большая глубина не означает полный перебор всех клеток.

Автоматические тесты не гарантируют победу над любым человеком и не могут заменить понимание кода обоими участниками. Проверки отказов охватывают C++ new, но не каждый возможный отказ ОС или ncurses. Для защиты следует повторить команды на проверяемом компьютере и уметь объяснить измерения и ограничения.

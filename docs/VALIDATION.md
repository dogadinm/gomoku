# Результаты проверки

Проверено 15 ноября 2026 года на arm64 macOS (8 ядер) с Apple Clang. Замеры относятся к этому компьютеру и этой выборке, а не ко всем возможным партиям.

## Функциональность и ошибки памяти

- `make test`: 4 526 проверок правил, тактики, сохранения, истории и дебютов; ещё 2 483 546 сравнений доски `Board` (на ней работают и игра, и поиск) с отдельной медленной реализацией правил в тестах: легальность каждой клетки, включая двойную тройку, результат хода с захватами и уязвимой пятёркой, восстановление после `unmake`, инкрементальный ключ.
- `make sanitize`: оба набора проходят под AddressSanitizer и UndefinedBehaviorSanitizer.
- ThreadSanitizer (вручную: `c++ -Iinclude -std=c++17 -g -O1 -fsanitize=thread tests/tests.cpp src/rules/*.cpp src/ai/*.cpp -pthread`): многопоточный поиск без сообщений о гонках.
- `make ui-test`: управление ncurses через настоящий PTY, подсказка, панель оценки, undo, сохранение/загрузка, Swap2, просмотр истории, изменение размера и выход.
- `make memory-test`: 35 проверок отказа C++ выделений в ядре и отдельный сценарий постоянного отказа в UI с восстановлением и выходом.

## Глубина и время

### `make performance-test`

Партии строятся детерминированным генератором случайных ходов (seed 1701), позиции берутся на разных стадиях. Поиск использует реальный профиль истории, как интерфейс.

| Показатель | Результат |
| --- | ---: |
| Всего позиций | 90 |
| С доказанным результатом (победа/поражение найдены) | 76 |
| Остальные позиции | 14 |
| Минимальная завершённая глубина остальных позиций | 10 |
| Позиции без доказанного результата с глубиной менее 10 | 0 |
| Среднее время по всем позициям | 86,2 мс |
| Среднее время по позициям без доказанного результата | 221,3 мс |
| Максимальное время | 475,5 мс |

Тест завершается ошибкой, если нетерминальный результат не достиг десяти или среднее время превысило 500 мс.

### Позиции из партий движков

Более трудная выборка: 40 партий движка против своих версий, позиция каждые 4 полухода, один движок на партию (как в интерфейсе).

| Показатель | Результат |
| --- | ---: |
| Позиций | 339 |
| С доказанным результатом | 158 |
| Остальные | 181 |
| Из них с глубиной ≥ 10 | 164 (91 %) |
| Глубина 9 / 8 / 7 / 6 | 11 / 1 / 4 / 1 |
| Среднее время | 217 мс |
| Максимальное время | 474,6 мс |

Глубина ниже десяти встречается в острых позициях конца партии, где обе стороны имеют много четвёрок и захватов: каждая четвёрка требует ответа, и форсированные ветви сильно разрастаются. Лимит 472 мс не превышается.

Куда уходит время (профиль, один поток): генерация ходов ~30 %, обновление сводок клеток при ходе и отмене ~38 %, оценка ~21 %. Квисценс — около трёх четвертей узлов; VCF — около 1 % времени.

## Сила

`make arena-test`: два варианта начала, игра каждым цветом против соперников с глубиной 1 и 3 — восемь партий.

| Показатель | Результат |
| --- | ---: |
| Победы / поражения | 8 / 0 (в 1 и 4 потоках, повторные прогоны) |
| Ходы основного ИИ | ~90 |
| Ходы без доказанного результата с глубиной менее 10 | 0–1 за прогон |
| Среднее / максимальное время | 120–180 / 474 мс |

Переработка проверялась партиями против предыдущего движка: 20 начал из 2–3 камней, каждое обоими цветами, 420 мс на ход у обоих.

| Сравнение | Счёт |
| --- | ---: |
| Итоговый движок против исходного (до переработки) | 38 : 2 |
| Нелинейная цена захватов против линейной | 17 : 7 |
| Одна четвёрка в квисценсе против четырёх | 8 : 16 — отклонено |
| Ограниченный квисценс (8 полуходов) против 12 | 19 : 21 — равенство при большей глубине |
| Фильтр «только захваты, ломающие четвёрку» | 12 : 28 — отклонено |
| Поиск не останавливается на непроверенном мате до глубины 10 | 32 : 8 — принято |

Отклонены также aspiration windows (глубина не изменилась) и 8 потоков (глубина почти та же, в автоматических партиях не лучше 4). Ускорение генерации ходов в квисценсе (+20 % скорости) проверено на совпадение: в одном потоке на фиксированной глубине те же ходы, оценки и число узлов, что до изменения.

## Практические пределы

Поиск выборочный: ширина `3 + d/2` спокойных ходов, LMR и сужение ответов на угрозы. Большая глубина не означает полный перебор всех клеток. Число потоков зависит от ядер машины (до 4: восемь потоков дали лишь немного большую глубину, а в автоматических партиях не были лучше); на машине с одним-двумя ядрами глубина будет меньше. Важнее всего скорость одного ядра: замеры сделаны на Apple M-серии.

Автоматические тесты не гарантируют победу над любым человеком и не могут заменить понимание кода обоими участниками. Проверки отказов охватывают C++ new, но не каждый возможный отказ ОС или ncurses. Для защиты следует повторить команды на проверяемом компьютере и уметь объяснить измерения и ограничения.

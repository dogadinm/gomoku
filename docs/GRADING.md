# Проверка перед защитой

Эта таблица связывает реализацию с пунктами присланной шкалы. Она не заменяет проверку правил на примерах, реальные партии против человека и объяснение алгоритма обоими участниками.

| Пункт | Где реализовано / что показать |
| --- | --- |
| Репозиторий и Makefile | Сборка из свежего клона; `make`, повторный `make`, `clean`, `fclean`, `re` |
| Правила | Показ: `./demo/play.sh 01…09` ([demo/README.md](../demo/README.md)). Код: `rules/board.cpp` (`State` в `rules/game.cpp` вызывает его), проверки захватов во всех направлениях, двойных троек, пяти и более, защитного захвата пятёрки |
| Интерфейс и таймер | Режимы 1–3, подсказка H, изменяющийся AI time; ncurses разрешён заданием |
| Улучшенный Minimax | `src/ai/` (`search.cpp`, `moves.cpp`, `threats.cpp`, `table.cpp`, `ai.cpp`): Negamax, alpha-beta, PVS, итеративное углубление, общая таблица транспозиций, квисценс, VCF, LMR, killer/history, Lazy SMP |
| Фактическая глубина | Depth — завершённая итерация главного потока (10 доводится до конца в пределах 472 мс), selective — с квисценсом; выборочная ширина описана в README |
| Несколько окон поиска | `Board`: счётчик камней в квадрате 5×5 вокруг каждой клетки; кандидаты — пустые клетки с ненулевым счётчиком |
| Alignments | `ai/evaluation.cpp`: формы, которые камень создаст в каждой пустой клетке (в т.ч. разорванные), для обоих цветов |
| Potential win by alignment | таблица форм `rules/patterns.cpp`: без места для пятёрки форма пустая |
| Freedom | Открытые (Flex) и закрытые (Block) формы имеют разные веса |
| Potential captures | `inspect()`: цели захвата, несколько пар одной целью, приближение к десяти захваченным камням |
| Captures | Отдельный компонент: 0 / 6 000 / 14 000 / 30 000 / 70 000 за 0–4 захваченные пары |
| Figures | Ход с двумя угрозами (открытая/двойная четвёрка, четвёрка + тройка, две тройки), захват с развитием линии, две клетки пятёрки |
| Players | Все статические и динамические компоненты отдельно для двух цветов; итог — разность с точки зрения игрока, которому ходить |
| Dynamic part | `historyProfile()` анализирует последовательность реальных действий; повторения направлений и захваты меняют вес позиций |
| Bonuses | Pro/Swap/Swap2, выбор правил, сохранение/загрузка, просмотр истории, undo, ИИ против ИИ; решение о раздельном зачёте принимает проверяющий |

## Команды

```sh
make -j
make test
make sanitize
make ui-test
make memory-test
make performance-test
make arena-test
make demo
./Gomoku --bench
```

В игре нажмите `V`, чтобы показать компоненты оценки для X/O. Таймер остаётся на экране. Тесты содержат позиции без места для пятёрки, все направления захвата и блокировки, разорванную четвёрку, победу несколькими захватами, защитную опору для будущего захвата и две разные истории, ведущие к одинаковой доске. Сохранение/загрузка и отмена действий проверяются вместе с профилем истории.

## Что ещё оценивается вручную

- Сила ИИ определяется партиями против человека, который пытается выиграть. Тактические тесты и самоигра не гарантируют результат по шкале 0–5.
- Измеряйте время на компьютере защиты и на разных стадиях партии. Бюджет 420 мс (жёсткий предел 472 мс) не является гарантией жёсткого времени ОС; число потоков зависит от ядер машины.
- Глубина ограничена временем и выбором кандидатов; десять уровней не гарантируются для любой позиции. Немедленная победа или доказанный проигрыш могут завершить поиск раньше.
- Оба участника должны объяснить отсечения, эвристику, профиль истории и ограничения выборочного поиска.
- Бонусы оцениваются после прохождения обязательной части. Количество зачтённых бонусов заранее не гарантируется.


Оптимизированные шаблоны и защитные захваты сравниваются с отдельными медленными реализациями. Проверки памяти включают постоянный отказ выделения в настоящем терминальном интерфейсе. Автоматические партии сохраняются в `build/arena-*.save`; их можно воспроизвести, скопировав выбранный файл в `gomoku.save` и нажав L. Замеры и результаты описаны в [VALIDATION.md](VALIDATION.md); подготовка обоих участников — в [DEFENSE.md](DEFENSE.md).
